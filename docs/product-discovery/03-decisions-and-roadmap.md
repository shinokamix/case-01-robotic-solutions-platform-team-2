# Решения и дорожная карта

## Статусы

- `Подтверждено` означает, что решение можно переносить в спецификацию.
- `Рабочее предложение` означает, что команда использует решение для планирования, но еще должна его подтвердить.
- `Нужен ответ` означает, что назначенный владелец должен принять решение.

Открытый вопрос не блокирует основу приложения. Он блокирует приемку указанного результата.

## Дорожная карта

### Этап 1. Подтвердить решения

Результат этапа:

- утвержден складской сценарий.
- определены обязательные ТТХ.
- согласованы цена, НДС и финансовые допущения.
- назначены владельцы данных и деплоя.

После этого команда может создать OpenSpec для основного сценария.

### Этап 2. Подготовить основу и данные

Работы:

- создать frontend, backend и PostgreSQL.
- добавить гостевую сессию и проверку владельца проекта.
- нормализовать каталог.
- подготовить схемы импорта.
- дополнить складские решения обязательными ТТХ.
- привязать характеристики к источникам.

Результат этапа:

- проект создается и сохраняется.
- импорт проверяет входные данные.
- другой пользователь не получает доступ к проекту.
- каталог готов к правилам подбора.

### Этап 3. Собрать складской сценарий

Работы:

- реализовать технический отсев и ранжирование.
- добавить объяснение результата.
- рассчитать текущий процесс, покупку и RaaS.
- добавить анализ чувствительности.
- связать расчет с 2D-имитацией.

Результат этапа:

- пользователь проходит путь от параметров склада до сравнения сценариев.
- одинаковые входные данные дают одинаковый результат.
- имитация показывает производительность и узкое место.

### Этап 4. Подготовить демонстрацию

Работы:

- добавить формы аэропорта и медицинского учреждения.
- сформировать PDF-отчет.
- развернуть демонстрационный стенд.
- проверить контрольный проект.

Результат этапа:

- чистое окружение запускается по инструкции.
- основной путь не требует ручного изменения данных.
- PDF совпадает с сохраненным проектом.
- демонстрация не зависит от внешних сайтов.

## Что не входит в discovery

Discovery не фиксирует:

- структуру репозитория.
- конкретные библиотеки backend.
- команды CI.
- полный набор тестов.
- формат внутренних таблиц базы.
- механизм деплоя для выбранной площадки.

Эти решения появятся в OpenSpec, ADR и задачах реализации.
