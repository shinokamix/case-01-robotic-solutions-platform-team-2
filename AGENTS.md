# Инструкции для агентов

## Перед изменениями

- Прочитайте ближайшие `AGENTS.md`, `README.md`, манифест пакета и затронутые спецификации.
- Перед изменением поведения проверьте актуальные спецификации и активные изменения в `openspec/`.
- Вносите минимальное изменение. Не исправляйте несвязанный код.
- Используйте команды из манифеста приложения или пакета. Не придумывайте корневые команды.

## Границы репозитория

- `apps/` содержит запускаемые приложения и сервисы.
- `docs/product-discovery/` содержит продуктовые требования и принятые решения.
- Считайте исходные PDF, DOCX, XLSX и CSV в `artifacts/` неизменяемыми.
- Не редактируйте `node_modules/`, `dist/`, результаты сборки и другие сгенерированные файлы.

## Правила монорепо

- Не импортируйте исходный код одного приложения из другого.
- Выносите общий код в `packages/` только после появления двух реальных потребителей.
- Публикуйте общий код через явный публичный API пакета.
- Храните команды разработки, сборки, линтинга и тестов в пакете. Корневые команды только координируют их.
- В локальном `AGENTS.md` указывайте команды, границы пакета, архитектурные ограничения и сгенерированные файлы. Не дублируйте корневые правила.
- При изменении публичного API обновляйте его потребителей и тесты.

## Проверки и безопасность

- Сначала запускайте проверки измененного пакета, затем общие проверки.
- В итоговом сообщении перечисляйте измененные файлы и выполненные проверки. Указывайте проверки, которые не удалось запустить.
- Не добавляйте секреты, токены, пароли и реальные персональные данные.
- Не удаляйте и не ослабляйте тесты ради прохождения проверки.
- Не меняйте CI/CD, зависимости, схему базы данных или публичные API без явного обоснования в задаче или спецификации.
