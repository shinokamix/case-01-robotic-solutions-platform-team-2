# Архивация изменения

## Выбери изменение

Если пользователь указал имя изменения, используй его. Иначе выполни `openspec list --json`.

Если список пуст, сообщи об отсутствии активных изменений и остановись. Если активно одно изменение, выбери его. Если изменений несколько, запроси имя одним сообщением и остановись.

Сообщи выбранное имя до следующего шага.

## Проверь готовность

```bash
openspec status --change "<имя>" --json
openspec instructions archive --change "<имя>" --json
```

При ошибке покажи ее и остановись.

Продолжай, если `schemaName` равен `spec-driven`, а список артефактов содержит только `specs` и `tasks`.

`specs` должен иметь статус `done` или `skipped`. `tasks` должен иметь статус `done`. При расхождении покажи статус и остановись.

Если ответ содержит `context`, примени его. Выполни каждый совместимый пункт из `operationGuidance`.

Шаги скилла, явный выбор пользователя, проверки и значения CLI имеют приоритет. При конфликте с `context` сохрани приоритетное значение. Покажи конфликт пользователю.

Пропусти несовместимый пункт `operationGuidance` и объясни причину.

Прочитай `tasks.md` по пути из `artifactPaths.tasks.existingOutputPaths`. Продолжай, если каждая задача отмечена как `- [x]`.

Если остались задачи `- [ ]`, перечисли их и остановись. Следующий шаг: `$openspec-apply-change` для Codex или `/openspec-apply-change` для Claude Code.

## Проверь изменение

```bash
openspec validate "<имя>" --strict --no-interactive
```

При ошибке покажи результат проверки и остановись.

## Архивируй изменение

Если пользователь явно просит не обновлять основные спецификации, добавь `--skip-specs`. Иначе выполни команду без этого флага.

```bash
openspec archive "<имя>" --yes --json
```

Выполняй обновление спецификаций и перенос изменения только через `openspec archive`.

При ошибке покажи ее и остановись.

После успешной команды проверь путь из поля `path` в JSON-ответе. Затем выполни `openspec list --json`.

Работа завершена, если путь из поля `path` существует, а изменение отсутствует в списке активных.

В ответе укажи имя изменения, поле `path`, поле `specsUpdated` и результат строгой проверки. Если использован `--skip-specs`, укажи это отдельно.
