# Подготовка изменения

Создай план из `specs` и `tasks`. Заверши процесс после подготовки плана. Реализация начинается отдельным вызовом.

## Определи изменение

Выведи из запроса цель и имя изменения на английском языке в `kebab-case`.

Если цель допускает несколько существенно разных трактовок, запроси решение одним сообщением и остановись. Остальные детали выясни из репозитория при создании артефактов.

При конфликте с существующей спецификацией или конфигурацией OpenSpec покажи конфликт и остановись.

## Создай изменение

```bash
openspec new change "<имя>"
openspec status --change "<имя>" --json
```

Продолжай, если `schemaName` равен `spec-driven`, а список артефактов содержит только `specs` и `tasks`. При расхождении покажи результат и остановись.

## Создай артефакты

Обработай `specs`, затем `tasks`. Для каждого артефакта:

1. Выполни `openspec instructions <артефакт> --change "<имя>" --json`.
2. Прочитай файлы из `dependencies`.
3. Выполни `instruction` с учетом `context`, `rules` и `template`. Запиши результат в `resolvedOutputPath`.
4. Выполни `openspec status --change "<имя>" --json`.

Для `specs` запроси путь возможности, если `resolvedOutputPath` и инструкция оставляют его неопределенным. Если инструкция требует `skip_specs: true`, запиши параметр в `.openspec.yaml` и переходи к `tasks`. Продолжай при статусе `done` или `skipped`.

Для `tasks` продолжай при статусе `done`.

## Проверь результат

```bash
openspec validate "<имя>" --strict --no-interactive
openspec status --change "<имя>"
```

При ошибке выполни решение из инструкции артефакта, если оно сохраняет согласованное поведение. Иначе покажи ошибку и остановись.

Работа завершена, если строгая проверка прошла, `specs` имеет статус `done` или `skipped`, а `tasks` имеет статус `done`.

В ответе укажи имя и путь изменения, пути и статусы артефактов, результат проверки. Следующий шаг: `$openspec-apply-change` для Codex или `/openspec-apply-change` для Claude Code.
